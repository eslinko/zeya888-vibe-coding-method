## Список стори — буллеты по проектам

**Когда:** нужно быстро увидеть, что уже создано, сгруппировав по проектам.  
**Параметры:** нет.

```text
выпиши в диалог сгруппировав по проектам буллет списком ссылки на созданные стори
```

---

## Список стори — вертикальный список

**Когда:** нужен вертикальный список ссылок с группировкой по проектам.  
**Параметры:** нет.

```text
выпиши все стори ссылками вертикальным списком с группированием по проектам
```

## Список стори — пути через запятую

**Когда:** нужен компактный paste путей от корня workspace для следующей волны.  
**Параметры:** нет.

```text
выпиши все стори путями от корня ворспейса списком через запятую
```

## Закрытие гапов стори (только REQ-уровень)

**Когда:** по gap-анализу нужно нарезать стори только на уровне требований, без реализации в тексте стори.  
**Параметры:** `$gapAnalysis` — путь/ссылка на gap-анализ (или `@` файл).

```text
для закрытия каждого гапа $gapAnalysis сделай в подходящих проектах и пакетах столько сколько нужно стори, только на уровне требований, без описания реализации в стори (это будет в проектных фокусных диалогах)
```

---

## Глубокая проработка стори (tech + субтаски)

**Когда:** список стори уже есть — нужно техническое решение и субтаски по каждой.  
**Параметры:** `$storyList` — список путей/ссылок на стори.

```text
$storyList
вот эти стори проработай вглубину (продумай техническое решение, потом по каждой стори отдельно проработай на базе решения все технические субтаски)
```

---

## Субтаски из уже принятой tech-архитектуры

**Когда:** целевая tech-архитектура уже есть в диалоге/доках — добить субтаски во всех созданных стори.  
**Параметры:** нет (опора на архитектуру из контекста диалога).

```text
во всех созданных стори проработай на базе созданной технической архитектуры все технические субтаски
```

---

## UX auto-accept рекомендаций

**Когда:** идут Decision-point / варианты — принимать UX-рекомендации без остановки, с отчётностью в чате.  
**Параметры:** нет.

```text
продумывай и принимай (автоматически без остановки но с отчетностью в диалоге) по каждому вопросу рекомендации из позиции UX удобства и элегантности согласованности всей архитектуры со всех ключевых позиций
```

## Объясни ситуацию простыми словами

**Когда:** нужна человеческая сверка «где мы сейчас» без жаргона.  
**Параметры:** нет.

```text
простыми словами объясни суть текущей ситуации
```

## Стыковки после sibling REQ

**Когда:** соседний REQ выполнен — дополнить остальные REQ пакета стыковками по факту кода.  
**Параметры:** `$siblingReqCompleted` — путь/имя выполненного sibling REQ.

```text
$siblingReqCompleted
выполнен, изучи код по связи с созданными на его основе стори, дополни остальные req из этого пакета детализацией по стыковкам где уместно
```

---

## Стыковки после выполненной стори

**Когда:** одна стори Done — стыковки только там, где разблокировалось, без выдумок.  
**Параметры:** `$story` — путь/ключ выполненной стори.

```text
$story
выполнен
по фактическому коду выполни стыковки (только где разблокировалось, ничего не выдумывай!) в следующих стори разных проектов из нашего плана
```
